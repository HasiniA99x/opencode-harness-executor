Step 1 · GitHub webhook

What starts an OpenCode review

The OpenCode PR-review path listens for the label ai-dlc/pr/pr-review-opencode on an open pull request.

Match-any rules

Any one of these webhook shapes can fire the execution block.

Labeled
action==labeled
Opened with label
action==opened
Synchronize
action==synchronize
// rules.json — github-pull-request-review-opencode
"match-any": [
  { "rule": "action==labeled&&label.name=='ai-dlc/pr/pr-review-opencode'&&pull_request.state=='open'" },
  { "rule": "action==opened&&pull_request.labels.*.name=='ai-dlc/pr/pr-review-opencode'&&pull_request.state=='open'" },
  { "rule": "action==synchronize&&pull_request.labels.*.name=='ai-dlc/pr/pr-review-opencode'&&pull_request.state=='open'" }
]

Inputs extracted

Passed into the execute-prompt as {{pr-number}}.

"use-inputs": [
  { "name": "pr-number", "value": "pull_request.number", "mandatory": true }
]
Not the same as Claude review. The classic Claude executor block uses label ai-dlc/pr/pr-review and image xianix-executor. OpenCode uses …/pr-review-opencode and xianix-executor-opencode.
