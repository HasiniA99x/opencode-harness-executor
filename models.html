Models you can run with OpenCode

OpenCode uses provider/model ids. Set model on the execution block and inject the matching API key via with-envs. Defaults used in this demo: openai/gpt-6.1-sol and anthropic/claude-sonnet-5-5.

Example rules.json model values

# format: provider_id/model_id
"model": "openai/gpt-6-luna"              # GPT-6 Luna · needs OPENAI-API-KEY
"model": "openai/gpt-6.1-sol"             # GPT-6.1 Sol (demo default)
"model": "openai/gpt-6-astra"             # GPT-6 Astra
"model": "anthropic/claude-haiku-5-5"    # Claude Haiku 5.5 · needs ANTHROPIC-API-KEY
"model": "anthropic/claude-sonnet-5-5"   # Claude Sonnet 5.5 (demo default)
"model": "anthropic/claude-opus-5-5"     # Claude Opus 5.5
"model": "google/gemini-3-pro"           # Gemini 3 Pro · needs Google credentials
Xianix wiring: the agent passes the rules model into the container as XIANIX-MODEL. Pair it with the right vault secret in with-envs.

Variants (optional)

OpenCode supports reasoning effort / thinking budgets per provider (high, low, max, …). Configure in OpenCode config when you need them; the harness mainly sets the base provider/model.
